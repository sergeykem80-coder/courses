# Django Admin Documentation - EduPlatform

## 📋 Обзор админ-панели

Админ-панель платформы предоставляет полный инструментарий для управления:
- Пользователями и их ролями
- Курсами, модулями и уроками
- Доступом студентов к курсам
- Прогрессом обучения
- Заказами и платежами

---

## 🔐 Разделы админ-панели

### 1. Пользователи (Users)

**Модель:** `User` + `UserProfile`

#### Основные возможности:
- ✅ Просмотр списка всех пользователей с фильтрацией по роли
- ✅ Создание/редактирование пользователей с назначением роли
- ✅ Массовые действия:
  - Активация/деактивация пользователей
  - Подтверждение email адресов
  - Смена роли (Студент / Куратор / Администратор)
- ✅ Предпросмотр аватара пользователя
- ✅ Инлайн-редактирование профиля (био, город)

#### Поля в списке:
| Поле | Описание |
|------|----------|
| Username | Имя пользователя |
| Email | Email (уникальный) |
| Role | Роль (student/curator/admin) |
| Is Active | Статус активности |
| Is Email Verified | Подтверждён ли email |
| Has Profile | Заполнен ли профиль |

---

### 2. Курсы (Courses)

**Модель:** `Category`, `Course`, `Module`, `Lesson`

#### CategoryAdmin
- Управление категориями курсов
- Авто-генерация слага из названия
- Быстрое редактирование слага в списке

#### CourseAdmin
- ✅ Полный CRUD курсов
- ✅ Inline-редактирование модулей
- ✅ Предпросмотр обложки курса
- ✅ Цветные бейджи статусов (Черновик/Опубликован/Архив)
- ✅ Подсчёт количества модулей и уроков
- ✅ Массовые действия:
  - Опубликовать выбранные
  - Вернуть в черновики
  - Архивировать

##### Поля курса:
```python
- title, slug (автогенерация)
- description, short_description
- cover_image (с предпросмотром)
- price, category, author
- status (draft/published/archived)
```

#### ModuleAdmin
- ✅ Редактирование модулей внутри курса
- ✅ Inline-уроки с предпросмотром видео
- ✅ Сортировка по order_index
- ✅ Подсчёт количества уроков

#### LessonAdmin (Kinescope интеграция)
- ✅ **Предпросмотр видео прямо в админке** через iframe Kinescope
- ✅ Поддержка двух способов добавления видео:
  1. Через `kinescope_video_id` (рекомендуется)
  2. Через готовый `kinescope_embed_code`
- ✅ Настройка бесплатного предпросмотра (`is_free_preview`)
- ✅ Форматирование длительности урока (мм:сс)
- ✅ Индикатор наличия видео
- ✅ Фильтрация по типу контента и курсу

##### Типы контента урока:
- `video` — видео из Kinescope
- `text` — текстовый материал
- `quiz` — тест (будущая функциональность)
- `attachment` — файл для скачивания

### 3. Доступ (Access)

**Модель:** `UserCourseAccess`, `LessonProgress`

#### UserCourseAccessAdmin
- ✅ Управление доступом пользователей к курсам
- ✅ Цветные индикаторы статуса (Активен/Истёк/Неактивен)
- ✅ Автоматическая запись выдавшего доступ (granted_by)
- ✅ Массовые действия:
  - Активировать/деактивировать доступ
  - Продлить доступ на 30 дней

##### Сценарии использования:
1. **Ручная выдача доступа** — создать запись вручную для пользователя
2. **Продление доступа** — массовое продление для группы студентов
3. **Отзыв доступа** — деактивация без удаления записи

#### LessonProgressAdmin
- ✅ Отслеживание прогресса студентов
- ✅ Просмотр времени просмотра (в формате мм:сс)
- ✅ Фильтрация по завершённым/незавершённым урокам
- ✅ Массовые действия:
  - Отметить как завершённые
  - Сбросить прогресс

---

### 4. Заказы (Orders)

**Модель:** `Order`

#### OrderAdmin
- ✅ Полный список заказов с фильтрацией
- ✅ **Статистика вверху страницы**:
  - Всего заказов
  - Оплачено
  - Ожидают оплаты
  - Общая выручка (₽)
- ✅ Цветные бейджи статусов заказов
- ✅ Ссылки на связанные объекты (пользователь, курс)
- ✅ Данные Robokassa (InvId, сумма, подпись, дата оплаты)

##### Массовые действия:
1. **Отметить как оплаченные и выдать доступ** — автоматическое создание `UserCourseAccess`
2. **Вернуть в ожидание оплаты** — сброс статуса и даты оплаты
3. **Отменить выбранные** — установка статуса cancelled
4. **Выдать доступ к курсам** — для уже оплаченных заказов

##### Workflow оплаты:
```
1. Пользователь создаёт заказ → статус: pending
2. Переходит на оплату Robokassa
3. Robokassa отправляет webhook → статус меняется на paid
4. Автоматически создаётся UserCourseAccess
5. Если webhook не прошёл → админ может вручную отметить как paid
```

## 🔍 Поиск и фильтрация

### Глобальные возможности:
- ✅ Поиск по email, имени пользователя, названию курса
- ✅ Фильтрация по дате (date_hierarchy)
- ✅ Фильтры по полям (status, role, category, etc.)
- ✅ Сортировка по большинству полей

### Примеры поисковых запросов:

```
# Поиск пользователя по email
admin/users/?q=user@example.com

# Фильтрация опубликованных курсов
admin/courses/course/?status__exact=published

# Заказы за последний месяц
admin/orders/order/?payment_date__gte=2026-01-01
```

## 🚀 Рекомендации по использованию

### Для администраторов:

1. **Создание курса:**
   - Создайте категорию (если нет)
   - Создайте курс с заполнением всех обязательных полей
   - Добавьте модули через inline
   - В каждом модуле добавьте уроки
   - Для видео-уроков укажите `kinescope_video_id`
   - Опубликуйте курс (статус → published)

2. **Выдача доступа:**
   - Через админку Access → UserCourseAccess → Добавить
   - Или через заказы: отметьте заказ как оплаченный → доступ выдастся автоматически

3. **Проверка прогресса:**
   - Access → LessonProgress
   - Фильтруйте по пользователю или курсу
   - При необходимости сбросьте прогресс

### Для кураторов:

- Просмотр всех курсов и уроков
- Редактирование контента уроков
- Просмотр прогресса студентов
- **Нет доступа** к управлению пользователями и заказами

## 🔧 Технические детали

### Требования к моделям:
- Все модели имеют `db_table` для явного указания имён таблиц
- Использованы `unique_together` для предотвращения дубликатов
- Индексы на часто используемых полях (user, course, status)

### Оптимизация:
- `select_related` для связанных объектов в list_display
- `prefetch_related` для many-to-many связей
- Pagination по умолчанию (Django admin)

### Безопасность:
- Только пользователи с `is_staff=True` имеют доступ
- Разграничение прав через `has_view_permission`, `has_change_permission`
- Логирование всех изменений (Django admin log)

## 📞 Поддержка

При возникновении проблем с админ-панелью:
1. Проверьте логи Django (`docker-compose logs backend`)
2. Убедитесь, что пользователь имеет роль admin и is_staff=True
3. Проверьте миграции: `python manage.py showmigrations`
